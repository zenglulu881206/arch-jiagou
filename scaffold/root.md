# 统一项目根骨架

所有绿场原型共用同一份根级目录契约；技术栈差异只出现在代码 adapter（如 Vue、GoFrame、Python 侧车）。`init.py` 负责创建目录和通用入口，Agent 根据选型生成具体文档内容。已有文件不覆盖。

| 路径 | 用途 | 生成方式 |
|---|---|---|
| `admin/AGENTS.md` | 开发侧自留地约束；打包、部署、E2E、清洗、授权签发等 | 复制模板；始终生成，运行包排除 |
| `admin/scripts/e2e_launch.py` | 浏览器验收统一启动入口 | 固定 overlay |
| `admin/release/` | 打包与部署脚本 | 空目录预留，按部署选型填充 |
| `agent/` | 分层 Harness | 目录预留；按选型生成对应 AGENTS |
| `docs/架构图/` | 架构图及索引 | 目录预留；Agent 按模板生成 |
| `docs/PRD及测试用例/` | 业务 PRD 与对应测试用例 | 目录预留；按业务闭环逐步生成 |
| `docs/项目特化/` | 项目词表、角色细表、脚本索引 | 目录预留；始终生成 README 索引 |
| `docs/旧低代码系统调研记录/` | 旧系统只读调研的唯一落点 | 目录预留；有调研时按模块分子目录 |
| `log/` | 实质性变更摘要和验收留痕 | 空目录预留；按项目规则记录 |
| `scripts/` | 通用开发辅助脚本 | 空目录预留 |
| `tests/` | 根级集成或端到端测试 | 空目录预留；单元测试优先放各技术栈惯用位置 |
| `CLAUDE.md` | Claude 兼容入口 | 指向根 `AGENTS.md` 的软链，不覆盖已有文件 |

## 验收边界

- `check-harness.py` 检查固定目录、必备 Harness/文档、模板深度和技术 overlay 目录。
- `verify.py` 检查所选且已支持的技术 adapter 的构建、测试、健康检查和浏览器冒烟。
- 选型对应的技术栈没有 adapter 时，仍可交付根骨架和架构文档，但必须标为「仅方案，未支持生成/运行验证」。不得把根目录齐全等同于技术脚手架可运行。
- 逆向/已有项目不运行 init；按目录契约核对并报告差异，不静默覆盖。
